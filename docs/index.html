What it looks for

  • JSON that changes shape Jackson 3 serializes enums through toString(), rejects null for primitives and ignores Jackson 2 serializers and customizers.
  • Configuration that is quietly ignored An ObjectMapper bean no longer replaces the default mapper. Renamed spring.jackson.* keys stop having any effect.
  • Infrastructure that stops running Flyway and Liquibase need a new starter. Spring Batch keeps its metadata in memory unless you ask otherwise.
  • Null handling that moved PropertyMapper skips null values by default.
  • The loud ones too Removed annotations, renamed starters, Undertow, test auto-configuration. You would find these anyway; the report lists them so you can plan.

18 rules today, each based on the Spring Boot 4.0 Migration Guide or the Jackson 3 default changes.

Why not just a rewrite tool?

Rewrite tools rename classes and move packages. That is the mechanical half of the upgrade, and you should use one. They do not tell you that your API now returns different JSON or that a property stopped applying. Boot4Check covers that half.

What it cannot do

  • It reads source code without resolving types, so some findings are false positives. Each rule states its confidence.
  • It sees only the dependencies your build files declare, not transitive ones.
  • A clean report is not proof that the upgrade is safe. It checks a fixed list of known changes.
